# 招聘信息抽取工具

把招聘网页批量整理成一张表格。

学校就业信息网上的招聘简章都是一个个网页，想对比岗位、筛选城市和学历要求，只能一页页点开看。
这个工具接收一批网页链接，自动抽出「公司、岗位、薪资、学历要求、工作地点」，汇总成一份 CSV，
可以直接用 Excel 打开排序筛选。

```

      正文长度 2733 字符
[2/3] 调用模型抽取岗位，并核对每个字段有没有依据...
      一次通过核对，所有字段都能在原文里找到依据
[3/3] 抽取完成，这个页面共 3 个岗位
      {'company': '洛阳智达石化工程有限公司', 'job_title': '工艺设计师', ...}
      {'company': '洛阳智达石化工程有限公司', 'job_title': '管道设计师', ...}
      {'company': '洛阳智达石化工程有限公司', 'job_title': '设备设计师', ...}
```

抽出来的每个字段都会回原文核对一遍，核对不过的字段会带着提示重新抽取。
接口偶尔返回 5xx 或超时，程序会自己退避重试。

输出的 `output/result.csv`：

| --- | --- | --- | --- | --- |

| 洛阳智达石化工程有限公司 | 设备设计师 | 5000-6500元/月 | 本科 | 洛阳 |

一个页面里如果列了多个岗位，每个岗位单独输出一行，公司名这类页面级信息在每行重复填写，
这样表格可以直接排序筛选。原文里没有提到的字段留空，不会编造内容。

## 工作原理

整条流程分四步：

1. **抓取**：`requests` 下载网页，`BeautifulSoup` 删掉脚本和样式标签，只保留正文文本。
2. **抽取**：把正文和字段说明拼成提示词，发给 DeepSeek，要求它按 json 格式返回结果。
3. **校验**：把每个字段的值回原文核对。做法是把值和原文都去掉空格标点、统一小写，
   然后检查值里的数字和最长汉字片段有没有在原文出现过。对不上就带着提示重新抽取，最多两轮。
4. **输出**：把通过核对的 json 转成字典，多条结果写进一个 CSV 文件。

核心思路是：**抽取规则不写在代码里**。传统爬虫要针对每个网站手写正则或选择器，网站改版就得重写；
这里把理解正文的活交给模型，换一个网站不用改代码。想抽别的字段，只改 `config.py` 里的 `FIELDS`。

模型会编，所以不能直接信它的输出，第三步的核对就是用来兜住这种情况的。

## 安装与运行

```bash
pip install -r requirements.txt
```

复制 `.env.example` 为 `.env`，填入自己的 DeepSeek API Key：

```
DEEPSEEK_API_KEY=sk-你的key
```

运行：

```bash
python main.py "网址1" "网址2" "网址3"
```

结果保存在 `output/result.csv`。

## 目录结构

```
config.py    要抽取的字段、模型名、抓取参数
fetch.py     下载网页并清洗成正文
extract.py   拼提示词、调用模型、解析返回值、核对不过时重试
verify.py    核对字段值在原文里有没有依据
main.py      命令行入口，串联整个流程并输出 CSV
tests/       校验器的自测脚本
```

## 已知限制与下一步

已经在做的：

- 模型偶尔会在 json 后面多写一段解释，`parse_json` 已经能容错，只取第一个 json 对象。
- 抽取结果会回原文核对，核对不过的字段带提示重新抽取，最多两轮；两轮后仍存疑的字段会保留并在日志里点出来。
- 部分站点（如 BOSS 直聘、51job）有反爬或整页 JS 渲染，暂时抓不到，需要换数据源或引入 Selenium。
- 岗位信息用表格排版的页面（如巴德富集团那份简章）现在能抽出多个岗位，但表格被 `get_text`
  拍平之后，岗位和学历、地点之间的对应关系是否可靠还没验证过，需要用下面的评测来量化。

计划中的改进：

- **准确率评测**：人工标注一批网页作为标准答案，计算字段级准确率，并和"直接让模型一次性抽取"的效果做对比。
- **列表页自动发现**：给一个列表页，自动找出其中所有详情页链接，不用手动贴几十条网址。
- **缓存**：同一个网址不重复调用模型，省 token。
